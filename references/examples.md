# Contoh keluaran

Tiga contoh singkat dengan genre berbeda. Semua `[ISI]` sengaja dibiarkan; itulah bentuk
yang benar ketika pengguna belum memberi data.

---

## Contoh 1 — Riset, versi cepat (diminta pengguna)

**Permintaan:** "versi cepat aja, kerangka skripsi tentang pengaruh TikTok ke minat beli mahasiswa"

### 1. Peta inti
| Node | Isi |
|---|---|
| Pembaca | Dosen pembimbing dan penguji `[CEK: program studi]` |
| Das Sollen | Keputusan beli idealnya didasari kebutuhan dan informasi produk yang cukup |
| Das Sein | Mahasiswa membeli produk yang dilihat di konten TikTok `[ISI: data awal/pra-survei]` |
| Gap | Belum diketahui seberapa besar konten TikTok memengaruhi minat beli mahasiswa `[ISI: kampus/kota]` |
| Tindakan | Rekomendasi untuk pemasar UMKM dan literasi konsumen mahasiswa |

### 2. Kerangka
1. **Latar belakang** — Tugas: meyakinkan penguji bahwa gap nyata. Isi: tren penggunaan TikTok `[ISI: sumber data resmi]`, pra-survei `[ISI]`. Panjang: 2–3 hlm.
2. **Rumusan masalah** — (a) Bagaimana pengaruh intensitas menonton konten TikTok terhadap minat beli? (b) Sejauh mana kredibilitas kreator memoderasi pengaruh tersebut? `[CEK: apakah variabel moderasi diperlukan]`
3. **Tinjauan pustaka** — teori minat beli `[ISI: teori yang dipilih + sumber]`, penelitian terdahulu (tabel 5 kolom) `[ISI: min. 5 artikel]`, kerangka pemikiran, hipotesis H1, H2.
4. **Metode** — kuantitatif, survei cross-sectional; populasi `[ISI]`; sampel `[ISI: rumus + alasan]`; kuesioner Likert 1–5, adopsi indikator `[ISI: sumber]`; uji validitas & reliabilitas; regresi `[CEK: moderated regression jika (b) dipakai]`; izin & consent.
5. **Hasil & pembahasan** — subbab 4.1 untuk (a), 4.2 untuk (b).
6. **Penutup** — 2 kesimpulan (satu per rumusan), saran praktis & penelitian lanjut.

### 3. Hasil cek
| Butir | Status | Perbaikan |
|---|---|---|
| U1 Pembaca spesifik | Lolos | Dosen penguji manajemen pemasaran |
| U2 Gap nyata | Menunggu data | Butuh data pra-survei atau statistik |
| U4 Tidak ada yatim | Lolos | (a)→4.1, (b)→4.2 |
| U8 Tindakan akhir | Lolos | |
| U9 Nol fakta karangan | Lolos | Semua data ditandai [ISI] |

| A7 Rumusan → data → analisis → subbab | Lolos | |
| A7 Rujukan nyata | Menunggu data | Teori dan penelitian terdahulu masih [ISI] |
| U12 Judul dari core claim | Lolos | Dicek setelah judul ditulis |

### 4. Opsi judul (sementara, karena U2 masih menunggu data)
1. Pengaruh Intensitas Menonton Konten TikTok terhadap Minat Beli Mahasiswa `[ISI: kampus]`
2. Pengaruh Konten TikTok terhadap Minat Beli dengan Kredibilitas Kreator sebagai Variabel Moderasi
3. Konten TikTok dan Minat Beli Mahasiswa `[ISI: kampus]`: Peran Kredibilitas Kreator

### 5. Yang perlu kamu lengkapi
- [ISI: data pra-survei atau statistik penggunaan TikTok dari sumber resmi]
- [ISI: kampus/kota, populasi, rumus sampel]
- [ISI: teori minat beli dan 5 penelitian terdahulu yang sudah dibaca]
- [CEK: pedoman penulisan kampus]

## Contoh 2 — Persuasi, brosur, mode Cepat

**Permintaan:** "brosur klinik gigi baru di Bekasi"

### 1. Peta inti
| Node | Isi |
|---|---|
| Pembaca | Keluarga dengan anak di sekitar `[ISI: kecamatan]` |
| Is | Takut ke dokter gigi, antre lama `[CEK: validasi dengan calon pasien]` |
| Should | Periksa gigi rutin tanpa cemas dan tanpa menunggu lama |
| Tindakan | Booking pemeriksaan pertama via WhatsApp |

### 2. Kerangka (lipat tiga)
1. **Sampul** — nama klinik, janji: "Periksa gigi keluarga, datang sesuai jadwal" `[CEK: benar-benar ada sistem jadwal]`, foto ruang praktik asli.
2. **Panel lipatan** — penawaran pembukaan `[ISI: jika ada]`.
3. **Dalam kiri** — dokter: nama, gelar, STR `[ISI]`.
4. **Dalam tengah** — layanan (4–6) dengan manfaat singkat, dan layanan anak.
5. **Dalam kanan** — harga mulai `[ISI]`, jam praktik, cara booking dalam 3 langkah.
6. **Belakang** — alamat, peta, QR WhatsApp, nomor.

### 3. Hasil cek
| Butir | Status | Perbaikan |
|---|---|---|
| Satu pembaca-tindakan-janji | Lolos | |
| Bukti nyata | Menunggu data | Belum ada testimoni; jangan dikarang, pakai kredensial dokter |
| Klaim diatur | Menunggu data | Iklan layanan kesehatan: hindari "terbaik", "tanpa rasa sakit" `[CEK: aturan iklan kesehatan]` |

| CTA awal = akhir | Lolos | Booking via WhatsApp di sampul dan panel belakang |

### 4. Opsi headline (sementara)
1. Periksa Gigi Keluarga, Datang Sesuai Jadwal
2. Klinik Gigi Keluarga di `[ISI: lokasi]`, Booking Lewat WhatsApp
3. Gigi Anak Diperiksa Tanpa Antre Lama `[CEK: sistem jadwal berjalan]`

### 5. Yang perlu kamu lengkapi
- [ISI: kecamatan, nama & STR dokter, daftar layanan, harga, jam, nomor WA]
- [CEK: sistem booking terjadwal benar-benar berjalan]

## Contoh 3 — Teknis, README

**Permintaan:** "outline README untuk CLI konversi CSV ke JSON yang saya buat"

### 1. Peta inti
| Node | Isi |
|---|---|
| Pembaca | Developer yang perlu konversi cepat di terminal |
| Is | Harus menulis skrip sendiri tiap kali |
| Should | Satu perintah, hasil JSON valid |
| Tindakan | Instal dan jalankan contoh pertama |

### 2. Kerangka
1. `# [ISI: nama]` — satu kalimat: "Ubah file CSV menjadi JSON dari terminal."
2. **Contoh output** — potongan CSV 3 baris dan JSON hasilnya `[CEK: hasil nyata dari tool]`.
3. **Instalasi** — `[ISI: npm/pip/binary]`, versi runtime minimal `[ISI]`.
4. **Quick start** — satu perintah `[CEK: dijalankan]`.
5. **Opsi** — tabel flag: nama, default, arti `[ISI dari --help]`.
6. **Kasus khusus** — delimiter, header kosong, encoding `[ISI: perilaku sebenarnya]`.
7. **Kontribusi & tes** — cara menjalankan tes.
8. **Lisensi** `[ISI]`.

### 3. Hasil cek
| Butir | Status | Perbaikan |
|---|---|---|
| Jenis Diátaxis tidak dicampur | Lolos | README = quick start + reference ringkas |
| Perintah diuji | Menunggu data | Jalankan semua contoh sebelum rilis |
| Tanpa rahasia | Lolos | |

### 4. Opsi judul
Judul mengikuti nama tool `[ISI]`. Opsi kalimat pembuka:
1. Ubah file CSV menjadi JSON dari terminal.
2. Konversi CSV ke JSON dengan satu perintah.
3. CSV masuk, JSON valid keluar.

### 5. Yang perlu kamu lengkapi
- [ISI: nama tool, cara instal, versi runtime, output --help, lisensi]
- [CEK: semua perintah contoh sudah dijalankan]

## Contoh 4 — Laporan KKP, pedoman UAJM, mode Lengkap

**Permintaan:** "kerangka laporan KKP saya di Diskominfo, bagian pengelolaan jaringan, kampus Atma Jaya Makassar"

Rujukan yang dibuka: `uajm-kkp.md`, `uajm-format.md`, `appendices.md`.

### 0. Variabel pedoman (sudah terjawab oleh pedoman UAJM FTI)
Empat bab · warna sampul hijau · tanpa abstrak · penomoran Arab bertingkat maksimal
4 tingkat · nomor tabel satu seri · gaya pustaka UAJM. Tidak ada yang perlu `[CEK]`
di sini karena pedomannya termuat; yang tetap `[CEK]` hanya hal di luar pedoman.

### 1. Peta inti
| Node | Isi |
|---|---|
| Pembaca | Pembimbing kampus (bobot 70%) dan pembimbing lapangan (30%) |
| Das Sollen | Pengelolaan jaringan mengikuti standar dan terdokumentasi |
| Das Sein | `[ISI: temuan observasi di divisi, mis. pencatatan perangkat masih manual]` |
| Gap | Selisih itu = "masalah" di §1.2 |
| Klaim inti | "Selama 42 hari kerja di divisi jaringan, penulis mengikuti `[ISI: n]` jenis pekerjaan yang menunjukkan `[ISI: temuan]`" |
| Bukti | Uraian teknis tiap jenis pekerjaan + dokumentasi foto |
| Tindakan | Saran ke instansi + pelajaran untuk prodi |

### 2. Kerangka
**BAB I PENDAHULUAN** — 1.1 Latar Belakang (kenapa KKP perlu; kenapa **Diskominfo**; kenapa **divisi jaringan** — dua alasan terakhir wajib eksplisit) · 1.2 Masalah · 1.3 Tujuan · 1.4 Manfaat · 1.5 Waktu dan Tempat (+ alamat lengkap) · 1.6 Jadwal Kegiatan (**alokasi per hari**). 4–6 hlm.

**BAB II TINJAUAN UMUM LOKASI KKP** — 2.1 Sejarah · 2.2 Kegiatan instansi · 2.3 Struktur organisasi (divisi KKP ditandai) · 2.4 Tujuan & fungsi **yang terkait bidang kajian** · 2.5 Sistem kerja. 5–7 hlm. Aturan pemangkas: sub-bab yang tidak dipakai lagi di Bab III dipotong.

**BAB III URAIAN TEKNIS PELAKSANAAN KKP** — disusun **per jenis pekerjaan**, bukan per tanggal. Tiap jenis: konteks → apa yang dikerjakan → aturan/standar → hasil → kesulitan & penanganan → bukti `[ISI]`. 40–50% halaman bagian utama.

**BAB IV PENUTUP** — 4.1 Kesimpulan (tiap butir menjawab satu tujuan di §1.3) · 4.2 Saran (tiap saran menempel pada kesimpulan atau penyimpangan yang disebut).

### 2b. Kerangka lampiran
```
Lampiran 1. Dokumentasi foto tiap jenis pekerjaan          [WAJIB]
  Dirujuk : §3.1–3.n     Ambil: selama magang — tidak bisa dibuat belakangan
Lampiran 2. Laporan harian/mingguan (Form Aktivitas)       [WAJIB]   Ambil: harian
Lampiran 3. Lembar perkembangan pembimbing kampus          [WAJIB]   Ambil: tiap konsultasi
Lampiran 4. Surat pengantar prodi & surat balasan instansi [BIASANYA]
Lampiran 5. Form penilaian pembimbing lapangan             [BIASANYA]
Lampiran 6. Daftar hadir seminar (≥5 peserta)              [BIASANYA]
```

### 3. Hasil cek
| Butir | Status | Perbaikan |
|---|---|---|
| U1 Pembaca spesifik | Lolos | — |
| U2 Gap nyata | Menunggu data | `[ISI: temuan observasi]` |
| K1 Lingkup masuk 3 kategori sah | Lolos | network administration |
| K2 §1.1 menjawab kenapa tempat & divisi | Menunggu data | tulis dua alasan itu eksplisit |
| K4 Tiap jenis pekerjaan punya rencana foto | **Gagal** | finalkan daftar jenis pekerjaan **sebelum** magang berakhir |
| K8 Tidak ada abstrak | Lolos | — |

### 4. Judul
Judul KKP memuat nama proyek yang dilaporkan → diberikan setelah §3.n final. Sementara: `[ISI: nama proyek]`.

## Contoh 5 — Dokumen organisasi, SK kepengurusan

**Permintaan:** "buatkan SK pengurus UKM periode baru"

Rujukan yang dibuka: `genre-organizational.md` §G3.

### 1. Peta inti
Should: organisasi punya dasar sah untuk bertindak · Is: kepengurusan baru belum ditetapkan ·
Gap: kekosongan dasar · Pembaca: pihak yang ditetapkan + pihak luar (kampus, sponsor) ·
Klaim inti: "Sejak tanggal ini, susunan berikut berlaku" · Bukti: konsideran + dokumen dasar ·
Tindakan: melaksanakan diktum. **Judul mengikuti format baku — bagian 4 dilewati.**

### 2. Kerangka
```
SURAT KEPUTUSAN <organisasi>
Nomor: [ISI: urut]/SK/[ISI: kode]/[ISI: institusi]/<bulan Romawi>/<tahun>
TENTANG PENETAPAN KEPENGURUSAN ... PERIODE [ISI]

MENIMBANG : a. bahwa ... ;  b. bahwa ... ;  c. bahwa perlu ditetapkan ... ;
MENGINGAT : 1. Statuta [ISI: nama institusi];
            2. Peraturan kemahasiswaan;
            3. [ISI: dokumen dasar + tanggal];
            4. Hasil musyawarah tanggal [ISI];
MEMUTUSKAN — MENETAPKAN
KESATU  : susunan pengurus sebagaimana Lampiran I
KEDUA   : tugas dan tanggung jawab pengurus
KETIGA  : siapa yang tidak termasuk (mis. anggota umum) + masa berlaku
KEEMPAT : klausul ralat
Ditetapkan di [ISI] · Pada tanggal [ISI] · [jabatan] · [ISI: nama + NIM]
LAMPIRAN I — Susunan pengurus
```

### 3. Hasil cek
| Butir | Status | Perbaikan |
|---|---|---|
| G7 Menimbang/Mengingat tidak tertukar | Lolos | alasan di Menimbang, dasar di Mengingat |
| G8 Diktum KESATU–KEEMPAT + klausul ralat | Lolos | — |
| G9 Nomor surat lengkap, bulan Romawi | Menunggu data | `[ISI: nomor urut]` |
| G10 Daftar nama di Lampiran, dirujuk diktum | Lolos | — |
| G14 Tidak ada nama/nomor dikarang | Lolos | semua `[ISI]` |
